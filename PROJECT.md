# Smart Launcher 1.0

> **Самая первая версия**

Этот файл — единая документация проекта: назначение, возможности,
интерфейс, архитектура, данные, безопасность, запуск, сборка, обновления,
публикация на GitHub, отличия от 0.3.0 и дальнейшее развитие.

## 1. О проекте

Smart Launcher — современный Windows-лаунчер сценариев на .NET 8 и WPF.
Он объединяет ежедневные действия в режимы: вместо ручного запуска
редактора, браузера, мессенджера, папки и файлов проекта пользователь
запускает одну подготовленную последовательность.

Режим содержит:

- название и описание;
- встроенную, пользовательскую или извлечённую из EXE иконку;
- индивидуальный цвет карточки;
- упорядоченный список действий;
- состояние каждого действия;
- проектные папки и несколько наборов файлов;
- сведения, необходимые для безопасной остановки процессов.

## 2. Системные требования

- Windows 10/11 x64;
- .NET 8 SDK — для запуска и сборки исходников;
- Inno Setup 6 — только для создания установщика.

## 3. Дизайн и навигация

Интерфейс выполнен в виде современной desktop-панели:

- собственная рамка окна и собственные кнопки управления;
- тёмная и светлая темы;
- настраиваемая прозрачность поверхностей;
- скруглённые панели, поля, кнопки и карточки;
- единая сине-фиолетовая система акцентов;
- PNG-иконки `Dashboard`, `Modes`, `Apps` и `Settings` вместо эмодзи;
- адаптация карточек под небольшое окно;
- читаемые hover-, pressed-, selected- и disabled-состояния;
- плавные переходы между страницами;
- приветствие с учётом времени суток.

Боковое меню:

- сворачивается до компактной панели с иконками;
- всегда имеет кнопку обратного открытия;
- сохраняет выбранное состояние между запусками;
- плавно меняет ширину с easing-анимацией;
- при закрытии подписи исчезают через fade и немного сдвигаются влево;
- при открытии подписи возвращаются через согласованные fade/slide-анимации;
- отображает версию `1.0` и подпись «Самая первая версия».

Рабочие страницы:

- «Главная»;
- «Режимы»;
- «Приложения»;
- «Настройки».

## 5. Редактор режимов

- создание, редактирование, дублирование и удаление режима;
- название, описание и цвет `#RRGGBB`;
- предварительный просмотр карточки до сохранения;
- визуальный выпадающий список иконок;
- встроенные иконки Smart Launcher;
- иконки найденных приложений;
- выбор собственного PNG, JPG или ICO;
- извлечение иконки непосредственно из EXE;

названиями, категориями и иконками. Пользователь выбирает приложение, а не
вводит путь к EXE вручную.

## 8. Запуск и остановка режима

- действия выполняются в заданном порядке;
- задержка между действиями настраивается от 0 до 5000 мс;
- уже работающие обычные приложения пропускаются;
- успехи, пропуски и ошибки отображаются в интерфейсе и уведомлениях;
- режим можно остановить отдельной кнопкой;
- Smart Launcher запоминает только созданные им процессы;
- при остановке повторно проверяются PID и время запуска;
- неизвестный, переиспользованный или неподтверждённый процесс не
  завершается;
- закрытие Smart Launcher не останавливает запущенные сценарии.

## 9. Интеграция с Windows

## 11. Данные и надёжность

Пользовательские данные находятся в `%LOCALAPPDATA%\SmartLauncher`:

- `modes.json` — режимы;
- `settings.json` — настройки;
- `apps.json` — каталог приложений;
- `Icons` — кэш иконок;
- `Logs` — журнал;
- `Backups` — резервные копии.

Защита данных:

- сохранение через временный файл;
- проверка JSON до замены основного файла;
- обычная `.bak`-копия;
- ротация пяти последних резервных копий;
- автоматический поиск последней исправной копии при повреждении JSON;
- импорт и экспорт режимов;
- импортированные команды помечаются недоверенными.

Журнал содержит:

- запуски;
- пропуски;
- ошибки действий;
- системные события;
- необработанные UI-ошибки;
- необработанные AppDomain-ошибки;
- необработанные Task-ошибки.

При критической ошибке пользователь получает понятное сообщение и путь к
log-файлу.

## 13. Запуск из исходников

Из папки `SmartLauncher.UI`:

```powershell
dotnet run --project SmartLauncher.UI.csproj
```

Проверка Debug и Release:

```powershell
dotnet build SmartLauncher.UI.csproj -c Debug
dotnet build SmartLauncher.UI.csproj -c Release
```

Анализаторы .NET включены. Любое предупреждение считается ошибкой.
Промежуточные файлы сохраняются в
`%LOCALAPPDATA%\SmartLauncher\Build`, поэтому заблокированные `bin` и
`obj` в папке проекта не мешают сборке.

## 14. Распространение

### 14.1. Основная установленная версия

Основной вариант — обычная self-contained сборка без single-file. Она
запускается быстрее portable-варианта:

```powershell
dotnet publish SmartLauncher.UI.csproj -p:PublishProfile=installed-win-x64
```

Результат: `dist\installed-win-x64`.

Создание установщика:

```powershell
.\installer\build-installer.ps1
```

Результат: `dist\installer\SmartLauncher-Setup-1.0.0.exe`.

Inno Setup выполняет:

- установку в профиль пользователя;
- создание пункта меню «Пуск»;
- опциональное создание ярлыка;
- опциональный автозапуск;
- регистрацию удаления;
- корректное обновление установленной версии.

### 14.2. Portable-версия

```powershell
.\installer\build-portable.ps1
```

Результат: `dist\portable-win-x64\SmartLauncher.exe`.

Portable остаётся одним self-contained EXE, но не является основным
вариантом распространения.

## 15. Автоматическое обновление

Механизм обновления:

1. загружает JSON-манифест по HTTPS;
2. сравнивает опубликованную и текущую версии;
3. показывает описание релиза;
4. загружает установщик с прогрессом;
5. обязательно проверяет SHA-256;
6. запрашивает подтверждение пользователя;
7. запускает установщик.

GitHub Release для каждого тега `vX.Y.Z` содержит:

- `SmartLauncher-Setup-X.Y.Z.exe`;
- `SmartLauncher-portable-X.Y.Z.exe`;
- `update-manifest.json`.

Стабильный URL проверки:

```text
https://github.com/OWNER/SmartLauncher/releases/latest/download/update-manifest.json
```

После появления репозитория `OWNER` заменяется на GitHub login.

Локальное создание манифеста:

```powershell
.\installer\New-UpdateManifest.ps1 `
  -InstallerUrl 'https://github.com/OWNER/SmartLauncher/releases/download/v1.0.0/SmartLauncher-Setup-1.0.0.exe' `
  -Version '1.0.0' `
  -ReleaseNotes 'Smart Launcher 1.0 - First release'
```

Скрипт вычисляет SHA-256 и создаёт
`dist\installer\update-manifest.json`.

Безопасность обновлений:

- только HTTPS;
- обязательное совпадение SHA-256;
- отмена обновления при несовпадении;
- подтверждение перед установкой;
- для публичного релиза рекомендуется Authenticode-подпись.

## 16. Автоматический GitHub Release

Файл `.github/workflows/release.yml` запускается при отправке тега `v*`.
Workflow:

1. получает исходники;
2. устанавливает .NET 8 и Inno Setup;
3. проверяет совпадение тега с версией `.csproj`;
4. собирает установщик;
5. собирает portable EXE;
6. формирует манифест с реальным адресом GitHub Release;
7. вычисляет SHA-256;
8. создаёт GitHub Release и прикладывает три файла.

Создание релиза после подключения удалённого репозитория:

```powershell
git tag v1.0.0
git push origin main
git push origin v1.0.0
```

## 17. Что нужно для публикации репозитория

Рекомендуемый способ — предоставить Codex доступ к одному пустому
репозиторию:

1. В GitHub создать новый публичный репозиторий `SmartLauncher`.
2. Не добавлять при создании README, `.gitignore` и License.
3. В подключении GitHub для Codex разрешить доступ к этому репозиторию
   (`Only select repositories` → `SmartLauncher`) или ко всем репозиториям.
4. Передать ссылку вида
   `https://github.com/GITHUB_LOGIN/SmartLauncher`.

После этого можно:

- добавить `origin`;
- отправить ветку `main`;
- отправить тег `v1.0.0`;
- дождаться GitHub Actions;
- проверить Release и его три файла;
- зафиксировать реальный URL манифеста обновлений в приложении.

Альтернативный способ — установить GitHub CLI, выполнить интерактивный
`gh auth login` и сообщить, когда авторизация завершена.
